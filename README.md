# BroStom

ブロックでロボを組み立てて戦わせる、ロボット対戦ゲームのたたき台。
現状は **平面フィールドのデバッグ環境** と **エディタ** の 2 モード構成。

運動モデルは `ZMF (ZOE Motion Framework) Core v1.0.0` をそのまま実装している。

```bash
npm install
npm run dev
```

---

## 1. 2つのモード

| | |
|---|---|
| **EDIT** | コアブロックにパーツを生やしてロボを作る。ブロック単位の組み立てと、ボクセル単位の削り／盛り／塗り。 |
| **TEST FIELD** | 平地アリーナに出て動かす。敵機 3 体（2脚・4脚・1脚）が相手をする。 |

右上の `▶ TEST FIELD` / `← EDITOR` で往復。エディタでは `Enter` でも出撃できる。

### エディタ操作

| 操作 | |
|---|---|
| 左ドラッグ / ホイール | 視点回転 / ズーム |
| クリック | 青い枠（ソケット）に設置、パーツをクリックで選択 |
| `B` `L` `A` `F` `C` | ブロック / レッグ / アーム / フェイス / カスタム ボーン |
| `V` | 選択モード |
| `X` `Z` `P` | 削る / 盛る / 塗る（ボクセル加工） |
| `[` `]` | ブラシサイズ |
| `Del` | 選択パーツを削除（配下ごと） |

ソケットは **カーソルが乗っているパーツの分だけ** 表示される。全部出すと機体が線に埋もれるため。
「左右対称でつける」を入れると ±X 面への設置が自動でミラーされる。

### フィールド操作

| キー | |
|---|---|
| `W A S D` | 移動（機体前方基準） |
| `Space` | 上昇 / 接地中はジャンプ。押しっぱなしで飛行 |
| `Shift` | 下降 |
| `E` | ブースト |
| `F` | ロックオン / 解除、`Tab` でターゲット切替 |
| `1` `2` `3` | ABC レイヤー切替（Active / Balance / Cooling） |
| マウス | 視点、左クリックで射撃 |
| `R` | リスポーン |

## 2. パーツの仕組み

### コアブロック

銀色の 1×1×1 ブロック。ロボのルートで、削除できない。
**ローカル +Z が前方**（＝移動進行方向）、+Y が上。エディタの床に出ている水色の矢印がそれ。

### ブロック

1 ブロック = ワールド 1 ユニット = **8×8×8 ボクセル**。
ブロックの 6 面にさらにブロックやボーンを生やせる。

上級モードでは中身のボクセルを削る／盛る／塗れる。ここが効くのは見た目だけではない：

- **質量は「実際に詰まっているボクセル数」で決まる**
- **推力は「ブロック数」で決まる**

つまり **中を刳り抜くと、推力そのままで軽くなる** = 機動性が上がる。厚く詰めれば重く、粘る機体になる。

### ボーン

細長い骨パーツ。**中央が関節**で、手前半分は親側と一体、奥半分から先が可動部になる。

```
      親ブロック
          │
   ┌──────┴──────┐
   │  near half  │  ← 親と一体（ここに刺したブロックは動かない）
   ├─────●───────┤  ← 関節（ここが曲がる）
   │  far half   │  ← 可動（ここに刺したブロックが動く）
   └─────────────┘
          ↓ 先端にさらにボーンを繋げば「膝」になる
```

シャフトにはブロックを串刺しにできる（スロット）。長さは 2〜8、太さは細／太の 2 種。

| 属性 | 挙動 |
|---|---|
| **レッグボーン** | 脚。1 本なら跳ねる、2 本なら歩く、3 本以上ならカサカサ動く |
| **アームボーン** | 腕。移動中は歩調と逆位相で振り、ロックオン中はロック方向を向く |
| **フェイスボーン** | 顔。進行方向に傾き、ロックオン中はターゲットを向く |
| **カスタムボーン** | 軸・振幅・速さ・駆動ソース（常時／速度／推力／衝撃／ロックオン）を自分で決める |

> **「脚 1 本 / 2 本 / 3 本以上」は “脚の本数” で数えている。**
> レッグボーンの総数ではない。腿＋脛のように 1 本の脚をボーンで繋いだ場合、
> 上流にレッグボーンを持たないボーンだけを 1 本の脚として数える。
> そうしないと「膝のある二足歩行」が作れないため。

| §4 Assist Controller | `src/zmf/AssistController.js` | 予測重み付け追従（Kalman-lite）、比例航法、角速度リミッター、ソフト・オーバーライド |
| §3/§7.1 Angular Dynamics | `src/zmf/AngularDynamics.js` | クォータニオン姿勢、適応的バンク・ダンピング、向心力アシスト、適応的オートホライゾン |

| §7 Camera Dynamics | `src/zmf/CameraDynamics.js` | ターゲット先行視点、Gフォース・チルト、衝突回避優先パンニング、視点残存慣性 |

| §9 更新処理フロー | `src/zmf/ZMFBody.js` | 上記を仕様書の順序どおりに束ねたもの |

### 空中戦と地上戦の両立

仕様書は無重力前提だが、地上戦も気持ちよくする必要があるので次のように橋渡ししている。

- 重力は常にかかっているが、**上昇入力を握っている間だけ `gravityScale` が 0.14 まで落ちる**。
  「飛ぶと決めた瞬間に重さを買い戻す」ことで、空中では ZMF そのままの無重力挙動になり、
  離した瞬間から 0.3 秒で重さが戻ってくる。
- 接地中は推力が水平面に射影され、**脚の本数がそのままトラクション**になる（`grip`）。
  4 脚は速く、脚なしのホバー機はよく滑る。
- ζ（抗力）は接地中に少し増える。これが「地面に足が付いている感触」。

### 重さ・軽さの調整点

`computeStats()`（`src/core/Assembly.js`）が唯一の真実。ここから下流は全部これを読む。

| 出力 | 由来 | 効く先 |
|---|---|---|
| `mass` | 実ボクセル数 + ボーン長 | 加速度、ABC の効き |
| `thrust` | ブロック数 + 脚の本数 | 最大加速度 |
| `weightClass` | 質量 0〜1 正規化 | ζ の粘性、旋回権限、マウス感度 |
| `agility` | 推力重量比 | スプール、最高速、FOV |
| `extent` | リグの外接半径 | 当たり判定、カメラブーム長 |
| `gait` | 脚の本数 | 歩容 |

## 4. ディレクトリ

```
src/
  core/        データモデル：Assembly（パーツ木）/ Voxel（グリッド＋Greedyメッシャ）/ Rig（→Three.js階層）
  zmf/         運動モデル。シーンには一切触らない
  anim/        Animator：属性ごとの手続き型モーション
  game/        World / Robot / SimpleAI / FieldScene / Hud / PostFX
  editor/      EditorScene：ソケット設置とボクセル加工
  ui/          DOM パネルとスタイル
```

層はこの順に一方向依存になっている。

```
Assembly (データ)  →  Rig (Three.js)  →  ZMFBody (運動)  →  Animator (見た目)
```

セーブは localStorage、`書出` / `取込` で JSON ファイルにもできる。

## 5. 現状の割り切り

たたき台なので、以下は意図的に単純化してある。

- 当たり判定は機体 1 個につき球 1 個（AABB との距離判定）。パーツ単位の被弾判定はまだない。
- 武器はロックオン方向へのヒットスキャン 1 種類のみ。ダメージも距離で確率的に外れるだけ。
- 敵 AI は「好みの間合いを保って左右にジンクする」だけ。アシスト側に予測させる素材が目的。
- フィールドは平地＋柱＋浮遊床の固定レイアウト。
